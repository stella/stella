# Maintenance release

stella includes reliability and maintenance improvements.

## Packages

- [@stll/ai-catalog](https://github.com/stella/stella/blob/v0.9.80/packages/ai-catalog/CHANGELOG.md): Offer Gemini 4 Carbon on the Google and OpenRouter routes with its upstream rates, context window and generated capabilities. The offered model id types and option lists change with it, so code that matches them exhaustively has to handle the new id.
- [@stll/cli](https://github.com/stella/stella/blob/v0.9.80/packages/cli/CHANGELOG.md): Add `chat.threads.read-state.update` and `chat.threads.pin-state.update`: mark one of your chats read or unread, and pin it to the top of your list or unpin it. `chat.threads.list` now says, for each chat, whether you have read its latest answer and whether you pinned it, and takes `pinState` to list only pinned or only unpinned chats.
- [@stll/cli](https://github.com/stella/stella/blob/v0.9.80/packages/cli/CHANGELOG.md): `chat.threads.read-state.update` and `chat.threads.pin-state.update` describe that asking for the state a chat already has changes nothing and notifies none of your devices.
- [@stll/ui](https://github.com/stella/stella/blob/v0.9.80/packages/ui/CHANGELOG.md): `DayCalendar` blocks take a `tooltip` of `{ type: "text", content }` or `{ type: "actions", content }`. An actions tooltip opens as a popover on hover, focus or press, so its buttons can be reached by pointer and keyboard, and stays open after a press inside it until it is dismissed; keys and presses inside it no longer start a range selection.
- [@stll/ui](https://github.com/stella/stella/blob/v0.9.80/packages/ui/CHANGELOG.md): A day calendar block too short for two lines ends its title in an ellipsis; its caption gives way first. Each block is a size container, so a title can adapt to the block's width with a container query.
- [@stll/ui](https://github.com/stella/stella/blob/v0.9.80/packages/ui/CHANGELOG.md): `DayCalendar` paints a `topic` tone from a separate low-chroma set (`--topic-*` tokens), so time no matter claimed never shares a matter's colour.
- [@stll/cli](https://github.com/stella/stella/blob/v0.9.80/packages/cli/CHANGELOG.md): `entities.files.list` returns each file's size in bytes.
- [@stll/cli](https://github.com/stella/stella/blob/v0.9.80/packages/cli/CHANGELOG.md): `lists.verifications.get` returns each claim's qualifiers: caveats beside its verdict that never change it (the record is not expected to speak to the point, a cited fact has a different scope, every fact it rests on is unsourced, or it rests on a held fact).
- [@stll/cli](https://github.com/stella/stella/blob/v0.9.80/packages/cli/CHANGELOG.md): `lists.verifications.claim-reviews.create` requires `reason` on `override`, `reopen` and `record-conflict` actions and takes an optional one on `status`, which can now also be `needs-evidence` (open until the record can answer it; never accepted in bulk). `lists.verifications.claim-reviews.list` reads a verification's review history, newest first: who acted, when, the action, its reason, and the claim's disposition just before and after, filterable by claim, action kind and reviewer.
- [@stll/cli](https://github.com/stella/stella/blob/v0.9.80/packages/cli/CHANGELOG.md): Add `lists.fact-extractions.create`: stella reads evidence documents and proposes their facts, each citing the passage it comes from, as generation candidates to accept or reject.
- [@stll/cli](https://github.com/stella/stella/blob/v0.9.80/packages/cli/CHANGELOG.md): Generation candidates of fact items carry their proposed fact details: submitting accepts them, listing returns them, and accepting a fact writes them onto the item. Generation runs list who produced them. A candidate name is held to the task name bound and a source quote to 2,000 characters.
- [@stll/cli](https://github.com/stella/stella/blob/v0.9.80/packages/cli/CHANGELOG.md): `lists.source-documents.update` marks a document as testimony (a witness statement, interview note or transcript) or a record for one list's facts, and `lists.source-documents.list` reads the kind of each named document. `lists.items.list` returns each fact's tier (`document`, `testimony` or `unsourced`); `lists.verifications.get` returns the tier of each pinned fact in place of `sourcing`, the `testimony-only` qualifier, and for a record conflict the fact suggested to govern it.
- [@stll/ai-catalog](https://github.com/stella/stella/blob/v0.9.80/packages/ai-catalog/CHANGELOG.md): Offer Claude Fable 5.2 with its upstream rates, 1M context window, and generated capabilities, and supersede Claude Fable 5 and 5.1 with it. The offered model id types and option lists change with it, so code that matches them exhaustively has to handle the new id.
- [@stll/cli](https://github.com/stella/stella/blob/v0.9.80/packages/cli/CHANGELOG.md): Read and update organization-wide AI instructions, including the `--ai-instructions` option for organization settings.
- [@stll/ui](https://github.com/stella/stella/blob/v0.9.80/packages/ui/CHANGELOG.md): `ReviewDecisionActions` takes `emphasis="quiet"` for a list of items whose one accent is a batch action. `ListItemTitle` gains a `statement` variant (a sentence clamped to two lines) and `ListItemDescription` a `paragraph` variant (two lines).
- [@stll/ui](https://github.com/stella/stella/blob/v0.9.80/packages/ui/CHANGELOG.md): `RunStateMark` (`@stll/ui/run-state-mark`) draws where a run of work stands: a bold warning `!` while it waits on the reader, `StatusMark`'s turning ring while it works. It has a React Native renderer under the `react-native` export condition.
